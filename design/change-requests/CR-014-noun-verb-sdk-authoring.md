### Principle (owner)
> "ALL AUTHORISATION IS A NOUN×VERB design. There is no reason to keep legacy authorisation."
>
> "Deliverable will be the default noun. If we have a noun defined, that defines the authorisation. No double gate."

`sdk_creator`/`sdk_approver` are the last Platform-badge hold-out after CR-006 moved every governed transition onto noun × verb. They go away; SDK authoring is gated by the **authored entity's** noun × verb.

### The authorisation rule
For an authoring surface of kind *K* (Pack / Template / Profile / TransitionDefinition):
- **If *K* has a defined noun** (all four will, after this CR) → authorisation is `K`'s noun × verb.
- **Else** → the default noun **`Deliverable`** governs (the authoring artifact *is* a Deliverable).
- **Never both** — the entity noun *replaces* the deliverable check for that surface; no double gate.

Two authoring authority levels per noun, reusing existing verbs:
- **`{noun}_define`** → author: view the surface, create draft, edit/save, submit.
- **`{noun}_publish`** → publisher: approve + publish/materialise.

(root bypasses, as everywhere.) e.g. `pack_define`/`pack_publish`, `template_define`/`template_publish`, `profile_*`, `transitiondefinition_*`.

### What's built here
1. **Nouns.** Add `Template`, `Profile`, `TransitionDefinition` to the authority vocabulary (`Pack` already exists). Add the `{noun}_define` / `{noun}_publish` pairs to the noun→verb **mapping** explicitly — they are authoring-authority pairs, not lifecycle transitions, so they don't come from the transition-derived mapping.
2. **Route gating** ([web/sdkAuthoring.ts](../../src/routes/seu/web/sdkAuthoring.js)). Replace `requireAnySdkBadge` / `requirePlatformBadge("sdk_*")` with a kind-aware gate that reads the actor's `badge_grants` and requires `{kind}_define` (author actions) or `{kind}_publish` (approve/publish). Update the `canCreate/canEdit/canApprove/canPublish` view flags. The `/authority/*` vocabulary-management routes (nouns/verbs/mapping/transition-definitions) are gated by `transitiondefinition_define` (they administer the governed vocabulary).
3. **No double gate** ([core/sdkAuthoring.ts](../../src/routes/seu/core/sdkAuthoring.js)). ~~The authoring flow drives an internal Deliverable through `transitionDeliverable` (+ Evidence transitions + Work Item). These run under a **system actor** so they never re-gate the author on `deliverable_*`~~ — **superseded by the 2026-08-17 bug fix above**: the indirection this point describes is removed entirely (entity-direct authoring), so there is no internal Deliverable left to double-gate, and no system actor.
4. **Seed.** Add Athens authoring users for the new badges so every surface is testable (mirrors the pack/objective user pattern).
5. **Retire `sdk_*`.** Remove every `sdk_creator`/`sdk_approver` code reference. The `badge_types` rows (migration `014`) are left in place (harmless, removing from a migration isn't idempotent-friendly) but nothing references them.

### Notes / decisions
- `{noun}_define` for Template/Profile/TransitionDefinition are authoring-authority badges, decoupled from any transition — consistent with [[creation-authority-not-a-transition]] (`define` is the birth verb; the badge is granted, not derived from a transition edge).
- ~~Running authoring-internal transitions as system supersedes the legacy `ensureAuthoringBadge` auto-grant~~ — superseded by the 2026-08-17 bug fix: `ensureAuthoringBadge` and the Deliverable it scoped grants to are both gone (entity-direct authoring).
