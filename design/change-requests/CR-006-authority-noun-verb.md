# CR-006 — Authority as **noun × verb** (clean, data-driven; Phase 10 badge model preserved)

**Raised:** 2026-08-13 · **Origin:** Chapter 1 §18 authority deep-dive · **Status:** ✅ **Closed 2026-08-13** — authorisation is now **noun × verb** (config 1a/1b + the enforcement collapse), dead legacy code deleted, green (unit **142/0/1**, dry-run **77/0**). **Scope** (reach gate) and **granting** are separate, tracked elsewhere (Chapter 1 §18.10/§18.11).

### Principle (Phase 10 unchanged — only the implementation is cleaned)
Authority is still **badge**-based. Phase 10's principles do **not** change. What was wrong is the *implementation*: it had grown hardcoded (per-entity `transitionX`, a role-fork, an `authority_rules` indirection, `if`-branch scope matching), and every new entity forced code. The clean statement the owner set (2026-08-13):

> **Authorization is an independent activity.** It does not depend on **role**, on **scope/layer** (Platform / Tenant / SEU — those fall out of FK relationships), or on **who owns** the entity. A governed transition is a **verb** applied to a **noun** (a "deliverable" in the generic sense — Objective, Evidence, Pack … all included). To authorize a transition you ask exactly one question: **does the actor hold the `noun_verb` badge the transition names?** Nothing else. Scope / reach / ownership is a **separate** axis (data isolation via FK), never part of the authorization decision.

### The model
- **Badge = `noun_verb`** (`deliverable_approve`, `objective_activate`, `pack_publish`). The pair *is* the authority; a grant = a holder holds that pair. No `governed_entity_type`, no `scope_id`, no role on the authority path.
- **Two vocabularies, both SDK-authorable:**
  - **Nouns — "Work outcome":** the entity types (today 11: SEU, Deliverable, Objective, Obligation, Evidence, Knowledge, Decision, KnowledgeScope, AttentionItem, ExternalInteraction, Pack, + Participant). Extensible → Document, Certificate … as data. (Also retires the hardcoded `entity_type` CHECK — a new noun is config, not a migration.)
  - **Verbs — "Work process":** create, review, approve, baseline, define … extensible → audit, close, archive, promote, assign, release … as data. **Global** vocabulary, reused across nouns.
- **Mapping (noun → allowed verbs):** which verbs are legal on each noun.
- **Transition Definition (the from→to graph we already have):** each transition row carries **exactly one verb** (from that noun's allowed set). That verb + the row's noun = the **required badge** `noun_verb`. This *replaces* the authority-rule lookup entirely.

These are the **four tabs** of the Transition Definition surface: **Work outcome (Nouns) · Work process (Verbs) · Mapping (noun + allowed verbs) · Transition Definition (from→to, each carrying its verb).**

### What this removes (the redundancy that was obstructing changes)
- **`authority_rules` table → retired.** It mapped a governed-transition code → `required_badge_type` (+ a display-only `authorised_role`). With the verb on the transition and the noun already on the transition, the required badge is `noun_verb` directly — the table is pure indirection.
- **`governed_entity_type` on `badge_grants` → gone** (the noun is in the badge).
- **Role fork in `transitionEngine` → gone** (no role consulted for authority).
- **Scope matching in `badgeAuthorityEngine` → out of the authorization decision.** Scope becomes **reach** (FK isolation), evaluated separately. The engine collapses to "holder holds the required `noun_verb`, badge Active" (root/`None` bypass preserved).
- **Generic `creator`/`approver` badges → `noun_verb` badges**, generated from the mapping, not hand-maintained.
- **Per-entity `transitionX` divergence → ONE orchestrator.** Objective is not special — it's just another noun. The only per-entity parts become data/hooks: a loader (which table), an apply step, and the side-effects tail. Omitting the authority step becomes structurally impossible.

### Creation is a transition too
The old "there's no `transition_definition` for create" gap disappears: a **birth** transition (∅ → initial state, e.g. → Defined) is just another row with a verb (`define` / `create`). Creation is authorized the same way — hold the `noun_verb`.

### Overlap review — verb per transition (done 2026-08-13, all 12 nouns)
Verified one-transition-to-one-verb across the seed graph. **No true collisions.** Findings:
- **Same state name → different verb across nouns** ("In Progress" = `create` for Deliverable but `start` for Obligation/AttentionItem) ⇒ the verb is **bound per transition on the Mapping**, never auto-derived from the state name.
- **Fan-in = one verb, many edges** (Objective `archive` ×3, Pack `activate` ×4, Participant `release` ×4 / `assign` ×2) collapses to a single `noun_verb` — authority is per verb, not per edge. This is the payoff, not an overlap.
- **KnowledgeScope promote = three verbs** (`promote_to_capability/enterprise/platform`), matching the three distinct authorities today — not one bare `promote`.
- Global verbs reused across nouns (validate, approve, archive, assign, analyse, propose, start, resolve, accept, supersede, acknowledge) stay distinct via the `noun_` prefix.

### Decisions to lock (why still Proposed)
1. Verb is **explicitly bound per transition**, not derived from the state name.
2. **Fan-in is one verb by design** — confirm.
3. **KnowledgeScope promote = three verbs** — confirm.
4. **Creation modelled as a birth transition** with a verb — confirm (closes the old create gap).
5. Where the vocabularies + mapping live end-to-end as data (tables, seedable, SDK-authored), and how existing seeds migrate **off** `authority_rules`.
6. **Scope is a separate, earlier gate — not removed, not part of authorization.** The pipeline is **two sequential checks, both must pass**: (a) a **scope/reach gate first** — "is this entity within the actor's reach?", determined by FK relationships (home tenant, and down through SEU where the FK chain says so); then (b) the **authorization gate** — "does the actor hold `noun_verb`?". SEU-level least-privilege (a creator whose reach is SEU-A cannot touch an SEU-B Deliverable) is **fully preserved** — it just lives in the scope gate, *ahead of* authority, instead of inside the badge. No behaviour is lost; scope simply stops being an input to the authority decision. (How fine the scope gate resolves — tenant vs. SEU vs. capability — and its own build are a separate concern from this CR's authority collapse.) **Noted for the Participant deep-dive:** the scope/reach gate may also govern **Participant access** (which participants an actor can reach); the exact implementation is deferred to the Participant module review.
